# Leader 0.4 Manual Design

## Goal

Publish a release-faithful, bilingual manual for `bluetape4k-leader` 0.4.x. The manual must help a reader select an election model and backend, integrate it with Spring Boot or Ktor, operate it safely, and learn from runnable examples without falling back to README-only documentation.

## Release boundary

- Release ref: `0.4.0`
- Release commit: `17ab7f872c1f96318c73d3580729cac20a67e017`
- Inventory: 35 Gradle projects — 17 published artifacts, 17 runnable examples, and 1 benchmark project.
- Authoring source: this branch on `develop`; API claims and repository links must resolve against the release ref.
- Exclude 0.5-only observation bridges, tag-cardinality controls, July benchmark results, Spring diagnostics, and post-release backend hardening.
- Keep DynamoDB, etcd, Consul, and Kubernetes Lease marked as preview in the 0.4 manual.

## Reader contract

The reader chooses one ecosystem version through `io.github.bluetape4k:bluetape4k-dependencies`. The manual must not ask the reader to coordinate a separate Leader BOM or per-module version.

Every module, example, and benchmark project receives an English and Korean landing page. Published-module pages explain selection, semantics, configuration, failure behavior, operations, testing, and source evidence. Example pages are workshop-grade: prerequisites, run command, observable result, failure diagnosis, and the next learning step.

## Information architecture

1. Overview: product fit, installation, repository map, runtime architecture, release/preview policy.
2. Guides: election model, execution model, backend, lease lifecycle, failure/cancellation, identity/state, framework selection, observability/operations, testing, migration boundaries, and learning paths.
3. Core: result semantics, options, single/group/strategic election, execution APIs, state/events/history, and lease extension.
4. Backends: Redis, Exposed SQL, document stores, control-plane leases, and cluster coordinators.
5. Frameworks: Spring Boot, Ktor, and Micrometer.
6. Projects: complete landing pages for all release projects.

## Diagram system

Manual diagrams use the established dark bluetape style, never pastel blog styling. Each diagram is stored as an editable SVG and a 2x PNG, uses visible arrowheads, keeps labels inside cards, and uses contrasting connector colors where routes overlap. Required diagrams:

- repository and learning map
- election lifecycle
- election/execution model decision map
- backend selection map
- framework and observability flow

Each diagram must pass the `bluetape-diagram` checklist and a full-size visual review.

## Validation

- Gradle inventory export and release inventory agreement.
- Manifest coverage for all 35 release projects.
- Bilingual path and section parity.
- Release-ref link validation.
- Markdown/frontmatter/link checks.
- Diagram SVG/PNG pair, dimensions, text bounds, connector, contrast, and full-size visual checks.
- Documentation-only CI; do not run expensive integration or security workflows without a code-relevant reason.
