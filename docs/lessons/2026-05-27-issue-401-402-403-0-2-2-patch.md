# Leader 0.2.2 패치 문제

## 맥락

Milestone `0.2.2`에는 세 가지 패치 문제가 있었습니다.

- #401: Mongo 그룹 선거인은 기록 기록기를 허용했지만 그룹 수명주기 이벤트를 내보내지 않았습니다.
- #402: AOP Micrometer 측정항목은 success적인 획득을 계산했지만 획득 대기 시간은 계산하지 않았습니다.
- #403: `FAIL_OPEN_RUN` 그룹은 기존 페일오픈 센티널을 재진입 범위로 처리하지 않았습니다.

## 결정

백엔드 잠금 토큰을 감사 토큰으로 사용하고 그룹 슬롯을 `slotId`로 사용하여 동기화, 비동기 및 일시 중지 경로를 통해 Mongo 그룹 기록을 연결합니다. 취소 의미를 변경하지 않고 잠금 해제 전에 터미널 기록 이벤트를 기록합니다.

success적인 AOP 획득 시 별도의 타이머로 `leader.aop.acquire.duration`를 추가하고 두 README 로케일에 모두 문서화합니다.

동기화 AOP 분기에서 백엔드 획득 전 단락 매칭 그룹 페일오픈 센티넬.

## 결과

패치는 종속성을 추가하거나 공개 API 형태를 변경하지 않고 #401, #402 및 #403을 닫습니다.

## 검증

- `./gradlew :bluetape4k-leader-mongodb:test --tests '*MongoLeaderGroupElectionTest*' --tests '*MongoSuspendLeaderGroupElectorTest*' --no-daemon` — 26개 통과.
- `./gradlew :bluetape4k-leader-micrometer:test --tests '*MicrometerLeaderAopMetricsRecorderTest*' --no-daemon` — 14개 통과.
- `./gradlew :bluetape4k-leader-spring-boot:test --tests '*LeaderGroupElectionAspectTest*' --no-daemon` — 18개 통과.
- `./gradlew publishAggregationToCentralPortal --dry-run --no-daemon --no-configuration-cache --no-build-cache` — success적인 작업 그래프 테스트 실행.
- `./gradlew publishToMavenLocal -x test --no-daemon --no-configuration-cache --no-build-cache` — success적인 로컬 게시.

## 미래 노트

- MockK 테스트의 경우 모의 항목을 클래스 필드로 유지하고 `@BeforeEach`에서 지웁니다. 이것은 이미 `bluetape4k-patterns`에 있습니다.
- 기록 레코드는 그룹 슬롯 키가 아닌 라이브 백엔드 토큰을 사용해야 합니다. `slotId`에 슬롯 식별자를 유지합니다.
- Maven Central 릴리스는 기존 태그, 빈 `snapshotVersion`, 릴리스 환경 승인 및 Central/서명 비밀 뒤에 유지되어야 합니다.
