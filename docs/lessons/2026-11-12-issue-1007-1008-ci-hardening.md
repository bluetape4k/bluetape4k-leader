# #1007/#1008 CI 결정성 보강 교훈

## 배경

Full Nightly의 `coverage-all` artifact는 Exposed core/JDBC/R2DBC에 대해 같은
source set을 H2·PostgreSQL·MySQL matrix로 반복 생성했다. 기존 집계기는
module 이름만 기준으로 모든 XML counter를 합산해 동일 instruction을 중복
계산했다. 별도로 Gitleaks CI는 `releases/latest` 다운로드와 `--no-git`
tree-only 검사를 사용해 설치 drift, 일시적 GitHub API 오류, 삭제된 secret의
history 누락에 취약했다.

## 결정

- Kover 집계의 논리 키를 `(module, report variant)`로 고정하고, 동일 키의
  후보는 denominator가 일치하는지 먼저 확인한다.
- 후보가 여러 개면 instruction coverage가 가장 높은 artifact를 대표값으로
  선택하고, 동률은 artifact/path 사전순으로 결정한다. 선택된 artifact를
  summary에 표시해 `TOTAL`의 계산 규칙을 추적할 수 있게 한다.
- Gitleaks `8.30.1` Linux x64 archive와 SHA-256을 고정하고, installer는
  bounded retry·checksum 검증·실패 시 non-zero 종료를 보장한다.
- CI는 `gitleaks git --log-opts="--all"`로 전체 history를 검사한다. 기존
  history의 두 false positive는 secret 값을 저장하지 않는 redacted baseline으로
  고정하고, 새 finding은 baseline으로 숨기지 않는다.

  선택

  `git diff --check` 통과

## 남은 경계

변경 branch는 아직 원격에 push하지 않았으므로 새 exact-head CI/Nightly와
GitHub hosted Gitleaks 설치 재현은 수행하지 않았다. 이 상태에서는 이슈를
닫거나 PR merge readiness로 승격하지 않는다.
