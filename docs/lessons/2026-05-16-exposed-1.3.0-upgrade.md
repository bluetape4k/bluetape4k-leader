# 강의: JetBrains Exposed 1.2.0 → 1.3.0 업그레이드

**날짜**: 2026-05-16 **문제**: #280 **PR**: #281 **영향을 받는 모듈**: `leader-exposed-core`, `leader-exposed-jdbc`, `leader-exposed-r2dbc`

## 요약

JetBrains Exposed를 `1.2.0`에서 `1.3.0`로 업그레이드했습니다. 버전 범프는 `gradle/libs.versions.toml`에서 한 줄 변경이었습니다. 외부 `ExposedR2dbcLeaderGroupElectionOptions` 변수를 숨기는 Exposed 1.3.0 `insert {}` DSL에 도입된 `options`라는 새로운 암시적 수신기 속성으로 인해 `leader-exposed-r2dbc`에 한 가지 컴파일 오류가 나타났습니다.

## 근본 원인

Exposed 1.3.0에서 `insert {}` 문 블록은 `options`(문 옵션)라는 속성을 노출하는 새로운 수신기를 얻었습니다. `ExposedR2DbcSuspendLeaderGroupElector`의 `recordAcquired()` 내부에서는 외부 `options` 필드에 대한 두 가지 액세스가 대신 새로운 내부 수신기에 대해 해결되었습니다.

```kotlin
// Before fix (broken in 1.3.0)
LeaderLockHistoryTable.insert {
    it[LeaderLockHistoryTable.lockOwner] = options.lockOwner          // 'lockOwner' unresolved
    it[LeaderLockHistoryTable.lockedUntil] = now.plusMillis(
        options.leaderGroupOptions.leaseTime.inWholeMilliseconds      // 'leaderGroupOptions' unresolved
    )
}
```

## 수정

람다를 입력하기 전에 로컬 변수로 값을 추출합니다. 이 패턴은 Exposed `insert/update/deleteWhere` 블록의 암시적 수신자 섀도잉에 대한 표준 수정 사항으로 프로젝트 메모리에 이미 문서화되어 있습니다.

```kotlin
// After fix
val lockOwner = options.lockOwner
val leaseTimeMs = options.leaderGroupOptions.leaseTime.inWholeMilliseconds
suspendTransaction(db) {
    val now = Instant.now()
    LeaderLockHistoryTable.insert {
        it[LeaderLockHistoryTable.lockOwner] = lockOwner
        it[LeaderLockHistoryTable.lockedUntil] = now.plusMillis(leaseTimeMs)
        ...
    }
}
```

## 검증

```
:leader-exposed-core:test   — BUILD SUCCESSFUL (all tests pass)
:leader-exposed-jdbc:test   — BUILD SUCCESSFUL (H2 + PostgreSQL + MySQL, Testcontainers)
:leader-exposed-r2dbc:test  — BUILD SUCCESSFUL (H2 + PostgreSQL + MySQL, Testcontainers)
```

## 향후 지침

- Exposed 버전이 올라간 후에는 `:leader-exposed-core:compileKotlin`, `:leader-exposed-jdbc:compileKotlin` 및 `:leader-exposed-r2dbc:compileKotlin`를 먼저 실행하세요.
- Exposed DSL 람다(`insert`, `update`, `deleteWhere`, `upsert`)의 새로운 암시적 수신기 속성을 살펴보세요. 람다 앞에서 충돌하는 외부 변수를 추출합니다.
- 암시적 수신자 섀도잉 패턴은 프로젝트 메모리(`feedback_exposed_lambda_shadowing.md`)에 있습니다.
